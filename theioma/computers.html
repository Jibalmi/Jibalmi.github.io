Network / Computers

One hub, the computers that dial in, and your phone.

One computer holds the database and the account’s certificate authority. Every other computer runs a small node agent and asks it for work. Nothing opens a public port.

The hub
Runs the orchestrator. It alone holds the database password and the certificate authority, and it leases every task.
A computer
A desktop with a GPU, a laptop, a cloud VM. It enrols with its own key, starts with no rights, and dials out.
A lease
A task belongs to one computer at a time. Its fencing token only goes up, so a late write from one that lost it is refused.
Your phone
Paired by a QR code. Low risk takes one tap; anything higher asks for your passkey or waits for your desk.

Network / Computers

How a computer joins.

These are the commands, from packages/node-agent and the hub’s channel script. Each step carries a note.

  1. 1

    Start the hub and its node channel

    On the computer that holds the database. The channel listens for mutual TLS on port 8821, on 127.0.0.1 unless you name a LAN or Tailscale address. The certificate authority is sealed with THEIOMA_SECRETS_KEY and never leaves the hub.

    noteThe channel starts when you opt in; this command opts in.

    # the web app, then the channel (from apps/web)
npm run dev:web
cd apps/web
THEIOMA_OWNER_USER_ID=<your user id> \
THEIOMA_NODE_CHANNEL_HOST=<LAN or Tailscale address> \
  node --conditions=react-server --import tsx \
  scripts/node-channel-hub.ts
  2. 2

    Make the new computer’s key

    From a checkout of the repository. The node agent makes a P-256 device key and prints its fingerprint.

    noteThe key is a file only you can read; the node agent can also keep it in the TPM or the Secure Enclave.

    # source is private during pre-release; access on request
cd THEIOMA && npm install
npx tsx packages/node-agent/src/cli.ts init \
  --state ~/.theioma-node
  3. 3

    Mint a code on the hub

    Open /settings/devices and choose Add a computer, with your passkey. The code has sixteen characters, works once and lasts ten minutes. Five wrong tries burn it.

    In the browser, on the hub: http://<hub>:3000/settings/devices
  4. 4

    Redeem it on the new computer

    The computer signs the code with its key and shows as pending on Devices.

    npx tsx packages/node-agent/src/cli.ts enroll \
  --state ~/.theioma-node \
  --hub-api http://<hub>:3000 \
  --code XXXX-XXXX-XXXX-XXXX --name laptop-02
  5. 5

    Confirm it, then grant it work

    On Devices, type the first eight characters of the fingerprint the computer printed, then use your passkey. The computer is active with an empty grant: it runs nothing until you give it harnesses, projects and folders.

    In the browser, on Devices: Confirm with passkey.
  6. 6

    Run it

    The node agent fetches a one-hour certificate, renewed every thirty minutes, and opens mutual TLS 1.3 to the hub. Its heartbeat carries its GPU’s memory and temperature and who holds its GPU lock.

    noteThe echo route answers dry runs, so you can check a node before you grant it a harness.

    npx tsx packages/node-agent/src/cli.ts run \
  --state ~/.theioma-node \
  --hub-api http://<hub>:3000 \
  --channel <hub>:8821 --echo-pty-route
  7. 7

    Revoke it when you need to

    On Devices, Revoke, with your passkey. Its certificate is refused from its next call, its leases are fenced, and its node agent exits with code 3. Sign it out of its harness logins at each provider yourself.

    In the browser, on Devices: Revoke.

Where you add a computer, confirm its fingerprint, and revoke it.

Every computer, its state, its key.

Each computer shows its state (pending, active or revoked), its key custody, its operating system, when it was last seen and when its certificate expires. At the foot of the list, the audit chain’s verdict.

  • Pending until you confirm the fingerprint with your passkey.
  • Active with an empty grant: it runs nothing until you grant it work.
  • Revoked is refused at its next call.

Network / Computers

Your computers, your keys, your certificate authority.

A computer joins with a key made on that computer and a single-use code. It gets a one-hour certificate from your account’s own certificate authority and talks to the hub only over mutual TLS 1.3. It starts with no rights and holds no database password.

The receipts.

Each measured line names the receipt it came from. Nothing on this page is a number that no run produced.

Measured, with its receipt

  1. Three node processes on one computer, each with its own device key and state folder.node-channel 06
  2. A spawn addressed to one computer ran on that computer only, with a 141 ms round trip.node-channel 06
  3. A revoked computer was dropped from the channel in 458 ms and 346 ms; its process exited with code 3 and its next spawn got 403.node-channel 06, node-facts
  4. Only TLS 1.3 with a current certificate from your account’s CA gets in. Another CA, an expired certificate, TLS 1.2, or a node posing as the hub: each is refused.NC-2, NC-3
  5. A stale lease token is refused, and a revocation advances the fence.NC-6, NC-7b
  6. No node holds the database URL or the internal secret: a scan of seven values found none.node-channel 06
  7. A 29 Sep 2026 test verified the audit chain for three node processes on one computer.node-channel 06
  8. A node reports its GPU; the hub read 16303 MiB, the card its own nvidia-smi saw.node-facts

The receipts are node-channel/06-two-node-proof.txt and node-facts/PROGRESS.md; the NC tests are in channel.integration.test.ts. The design and its threat model: 12-MULTI-COMPUTER-SECURITY.md.

Network / Computers

Questions.

Can I run it across several computers?

As a preview. Each computer you own enrols with its own key, receives a certificate from your account’s authority, and takes work leased to it over mutual TLS, with leases and revocation. The receipts were measured with three node processes on one computer. A second, physical Linux computer has been enrolled and sending heartbeats since 23 Oct 2026; work the hub sends to it is not proven yet. The steps are in how a computer joins.

Do I need a GPU?

No. Subscriptions and API providers carry the work without one. Local models and speech can use a GPU. A 6 Sep 2026 test with synthetic audio measured an 8.2 s spoken turn on an RTX 5080 and 23.1 s on the CPU; these are historical timings, not current-service performance. A local fine-tune uses it; there is no scheduled training job, since the monthly fine-tune was retired on 29 Oct 2026 and rented GPUs are refused. A computer with a GPU reports its memory and temperature to the hub.

What does it cost to run?

Theioma uses the subscriptions, API keys, free tiers and local models you connect. A usage ledger shows spend and subscription use per agent, project and computer.
