Benchmarks

The Benchmark Room.

What has been measured first: the speech model, a whole spoken turn and the node channel, each with its receipt. Then the three numbers that were asked for: what routing each call through the cost cascade saves, how long a task takes against one plain agent, and how often the work is right the first time. None of those three is ready to lead with. Each is below with its value, or with what it waits on, and every number carries its dates, its source and its caveat.

measured · not a headline

Tokens for the price of Claude Opus 5.5

What it is
How many tokens routing served for the list-price value it drew, against how many tokens that same value buys on Claude Opus 5.5 alone, as the app’s model scorecard computes it: the price Opus 5.5 lists for these tokens, type by type, divided by their recorded list-price value.
What it is not
Money spent or saved. Most of the work runs on included subscriptions and free routes: a subscription call counts at its list-price equivalent and a free or local call at zero. No plan publishes that its allowance follows list prices, so this is not a share of a subscription saved.
Why it is not a headline
It was read from the running app on one afternoon, over one operator’s own ledger, and it moves with the window: below one over the last seven days, because GPT-6-Astra lists above Opus 5.5, and above one over the last thirty.

Benchmarks

Speed and right first time: one bench, not run yet.

History cannot answer either question: no plain single-agent run was ever recorded on the same work. Both numbers come from one controlled bench, and a real run waits for the operator’s OK because it spends the operator’s Claude usage.

  1. two arms

    The same task, twice. One plain Claude Code session on Claude Opus 5.5, with no Theioma server, no router and no reviewer. Then the same prompt handed to Theioma’s project manager, which plans, spawns router-assigned workers and sends every task through the code, security and QA reviewers.

    METHOD §D.1

  2. hidden tests

    Hidden tests decide. Each task is a defect this repository fixed red-first, and its hidden acceptance is that lane’s own test. Neither arm sees it before declaring the work done. A failure gets the same fix message in both arms, word for word.

    METHOD §D.2

  3. rule first

    The rule came first. Right first time may lead only if McNemar’s exact test on the paired runs gives p < 0.05; speed only if its bootstrap interval over tasks excludes one. The tokens each arm spent are always shown beside the result.

    METHOD §D.5
